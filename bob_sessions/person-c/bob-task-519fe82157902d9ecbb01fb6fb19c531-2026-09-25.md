# # Code2Edge — Team Context & AI Prompt Kit

**Event:** IBM Bob 2.0 Hackathon (lablab.ai), Sep 25–27 2026, 48h build, solo/team allowed.
**Tagline:** *Deployment with proof.*

## Shared context (paste this into every AI conversation, regardless of role)

> Code2Edge is a Bob-native deployment workflow. A developer has a KWS (keyword-spotting, DS-CNN) model repository that works in Python but needs to run on a constrained MCU (STM32U585 on the Arduino UNO Q — Cortex-M33, 786 KB SRAM, 2 MB flash, no Python interpreter). The hard part isn't converting the model — it's that the audio preprocessing pipeline (resample → pre-emphasis → framing → FFT → Mel filterbank → log → normalization) is scattered across multiple files with constants buried in config. Reimplementing that chain in C/C++ for the MCU is where deployment silently breaks: a wrong window size, FFT convention, or normalization constant produces a model that runs but predicts differently.
>
> Code2Edge gives IBM Bob hardware awareness via an MCP server, and Bob does the actual repository-level engineering: trace the pipeline, generate equivalent C/C++, and then **prove** equivalence via differential parity testing (same audio corpus through Python reference vs. generated C++, measuring `max_abs_diff` / `mean_abs_diff` / prediction agreement / accuracy delta at each pipeline stage). If parity fails, the report is stage-wise, so Bob can localize the divergence and repair its own generated code — with a retry cap (3 attempts) before escalating to human debug.
>
> The UNO Q's Linux side (Dragonwing QRB2210, 2 GB RAM) runs the Python reference pipeline; the MCU side runs Bob's generated implementation. Final output is a git branch/PR (not a dashboard) containing the deploy code, tests, and a README, plus a predicted-vs-measured hardware table. Submission requires a public GitHub repo (including exported Bob session reports), a ≤5-min demo video, slides, and a small static evidence page — not a live-reachable hardware demo.
>
> MCP tools: `profile_model()`, `inspect_pipeline()`, `check_target()`, `run_parity_test()`, `benchmark_target()` (optionally `quantize_model()`).
> Fallback domain if KWS parity proves intractable on Day 1: IMU gesture recognition (lowpass → normalize → reshape → 1D-CNN), same architecture.

## Person A — Pipeline & Parity (critical path)

**Mission:** Prove that a generated C++ implementation of the KWS preprocessing chain can match the Python reference closely enough to preserve model accuracy — and build the harness that measures it.

**What you own:**
- `dump_reference.py` — instruments the *existing* repo's own preprocessing (don't hand-parse it; execute it and hook every stage) against a fixed ~500-sample corpus. Dumps intermediate tensors after each stage: post-resample, post-pre-emphasis, post-framing, post-FFT, post-Mel, post-log, post-normalize. This dump is the specification everything else is checked against.
- The generated/hand-written C++ preprocessing (`preprocess.cpp/.h`) reproducing that same chain, stage for stage.
- The parity harness: runs both pipelines on the same corpus, reports **per-stage** `max_abs_diff`, `mean_abs_diff`, cosine similarity, then end-to-end prediction agreement and accuracy delta.
- Do NOT promise bit-exact parity — target measurable, explainable divergence (aim: `max_abs_diff` in the 1e-5–1e-4 range on features; report whatever prediction-agreement % you actually get).

**Interfaces:**
- Consumes: nothing from B or C to start — this is the first thing built.
- Produces (by T+8h): reference tensor dump + manifest (shapes, dtypes, constants actually observed at runtime) → feeds Person C's `profile_model()`/`inspect_pipeline()` MCP tools.
- Produces (by T+24h): C++ preprocessing passing host parity → handed to Person B for MCU build.

**Day-1 spike (do before the event if rules allow, otherwise hour 0–8):** Freeze the reference dump. Then hand-reproduce ONE stage in C++ and measure real divergence. This number decides whether the project stays on KWS or pivots to IMU.

def build_resolver(schema_path: Path) -> RefResolver:
    """Build a RefResolver rooted at the contracts/ directory so that
    $ref: 'common.schema.json#/...' works regardless of $id values."""
    base_uri = CONTRACTS_DIR.as_uri() + "/"
    store = {}
    for schema_file in CONTRACTS_DIR.glob("*.schema.json"):
        doc = load_json(schema_file)
        schema_id = doc.get("$id", schema_file.as_uri())
        store[schema_id] = doc
        # Also register by bare filename for local $ref resolution
        store[schema_file.as_uri()] = doc
    return RefResolver(base_uri=base_uri, referrer={}, store=store)

def build_registry():
    """Build a jsonschema Registry (referencing library) from all schema files."""
    try:
        from referencing import Registry, Resource
        from referencing.jsonschema import DRAFT202012

        resources = []
        for schema_file in CONTRACTS_DIR.glob("*.schema.json"):
            doc = load_json(schema_file)
            schema_id = doc.get("$id")
            if schema_id:
                resources.append((schema_id, Resource.from_contents(doc, default_specification=DRAFT202012)))
            # Also register by file URI
            file_uri = schema_file.as_uri()
            resources.append((file_uri, Resource.from_contents(doc, default_specification=DRAFT202012)))

        registry = Registry().with_resources(resources)
        return registry, True
    except ImportError:
        return None, False


def validate_example(tool: str, registry, use_registry: bool) -> tuple[bool, str]:
    schema_path  = CONTRACTS_DIR / TOOL_SCHEMAS[tool]
    example_path = EXAMPLES_DIR / EXAMPLE_FILES[tool]

    if not schema_path.exists():
        return False, f"MISSING schema: {schema_path.name}"
    if not example_path.exists():
        return False, f"MISSING example: {example_path.name}"

    full_schema = load_json(schema_path)
    example     = load_json(example_path)

    if "$defs" not in full_schema or "Output" not in full_schema["$defs"]:
        return False, f"Schema {schema_path.name} has no $defs/Output"

    # Build a self-contained schema that wraps the full document as the root
    # and immediately $refs into Output, so all sibling $defs are resolvable.
    wrapper_schema = {
        "$schema": "https://json-schema.org/draft/2020-12/schema",
        "$defs": full_schema["$defs"],
        "$ref": "#/$defs/Output",

    try:
        if use_registry:
            validator = Draft202012Validator(wrapper_schema, registry=registry)
        else:
            validator = Draft202012Validator(wrapper_schema)

        errors = list(validator.iter_errors(example))
        if not errors:

        worst = max(errors, key=lambda e: len(e.absolute_path))

        return False, f"ValidationError at [{path_str}]: {worst.message}"

    except jsonschema.SchemaError as e:
        return False, f"SchemaError: {e.message}"
    except Exception as e:  # noqa: BLE001
        return False, f"Error: {e}"

                (schema_id, Resource.from_contents(doc, default_specification=DRAFT202012))

    "check_target":     "check_target.schema.json",

def _get_wrapper_schema(tool_name: str) -> dict:
    if tool_name not in _SCHEMA_CACHE:
        schema_file = _CONTRACTS_DIR / _TOOL_SCHEMA_FILES[tool_name]
        full = json.loads(schema_file.read_text(encoding="utf-8"))
        _SCHEMA_CACHE[tool_name] = {
            "$schema": "https://json-schema.org/draft/2020-12/schema",
            "$defs": full["$defs"],
            "$ref": "#/$defs/Output",
        }
    return _SCHEMA_CACHE[tool_name]


def validate_output(tool_name: str, payload: dict) -> None:
    """Validate *payload* against the Output schema for *tool_name*.

    Raises jsonschema.ValidationError on failure.  The caller (tool handler)
    is responsible for converting this to an MCP error response.
    """
    wrapper = _get_wrapper_schema(tool_name)
    validator = Draft202012Validator(wrapper, registry=_REGISTRY)
    errors = list(validator.iter_errors(payload))
    if errors:
        worst = max(errors, key=lambda e: len(e.absolute_path))
        path_str = " -> ".join(str(p) for p in worst.absolute_path) or "(root)"
        raise jsonschema.ValidationError(
            f"[{tool_name}] schema validation failed at [{path_str}]: {worst.message}"
        )

    payload: dict[str, Any] = json.loads(raw)

    return payload

## Environment variables

### Per-tool mode switch

```
CODE2EDGE_PROFILE_MODEL_MODE     = mock | real   (default: mock)
CODE2EDGE_INSPECT_PIPELINE_MODE  = mock | real
CODE2EDGE_CHECK_TARGET_MODE      = mock | real
CODE2EDGE_RUN_PARITY_TEST_MODE   = mock | real
CODE2EDGE_BENCHMARK_TARGET_MODE  = mock | real
CODE2EDGE_QUANTIZE_MODEL_MODE    = mock | real
```

**`mock`** — loads a fixture from `mcp_server/mocks/<tool>.json`, stamps a fresh `run_id` and `timestamp`, and sets `source="mock"`.

**`real`** — delegates to the matching adapter:
- `pipeline_adapter.py` (Person A's pipeline and parity outputs)
- `target_adapter.py` (Person B's hardware target outputs)

> **Never falls back silently from real to mock.** If the adapter raises `NotImplementedError`, the tool returns `{"status": "ERROR", "error_message": "<what Person A/B needs to implement>"}`.

### Parity scenario (mock mode only)

```
CODE2EDGE_MOCK_PARITY_SCENARIO = pass | fail_then_pass | always_fail | fail_mel_scale | fail_framing_shape
```

| Scenario | Behaviour |
|----------|-----------|
| `pass` | All 7 stages PASS; prediction_agreement ≥ 0.95 |
| `always_fail` | Every call: FAIL at `framing` stage (shape 49 vs 50 frames); diagnosis hints present |
| `fail_framing_shape` | Same as `always_fail` — explicit framing off-by-one |
| `fail_mel_scale` | FAIL at `mel` stage (constant scale error ~1.84, HTK vs Slaney filterbank); pre-mel stages PASS |
| `fail_then_pass` | First call per `run_id` → FAIL (framing shape); second call → PASS. Simulates successful repair loop. |

### Key design decisions

- **No silent fallback.** `real` mode that hits `NotImplementedError` returns `{"status": "ERROR", "error_message": "waiting on Person A/B: ..."}` — the agent sees exactly what needs to be implemented.
- **Schema validation is the gate.** Every tool calls [`validate_output()`](mcp_server/_schema.py) before `return`. A bad payload from the adapter will be caught before it reaches the agent.
- **`fail_then_pass` is stateful per `run_id`**, not per call count globally — so two parallel repair loops with different `run_id`s don't interfere.
- **Adapters are read-only wrappers.** They import from `tools/target/` or `src/pipeline/` if needed but never write there.
