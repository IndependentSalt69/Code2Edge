## 1. Prerequisites

| Tool | Version | Purpose |
|------|---------|---------|
| Python | ≥ 3.10 | Host runtime, MCP server, test suite |
| `arduino-cli` | ≥ 1.5 | Firmware compilation & flashing |
| `arduino:zephyr` core | 1.0.0 (`arduino:zephyr:unoq`) | STM32U585 toolchain |
| `gcc` / `clang` | system | Host-side C DLL build (`tools/build_c_dll.py`) |
| Git | ≥ 2.40 | Worktree-based deploy workflow |

**Hardware (Person B only):**
- Arduino UNO Q (STM32U585 MCU subsystem)
- Serial port on `/dev/tty*` or `COM3` at 115200 baud

## 2. Dev Environment Setup

```bash
# 1. Clone
git clone git@github.com:IndependentSalt69/Code2Edge.git
cd Code2Edge

# 2. Create and activate a virtual environment
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# 3. Install the project in editable mode with dev extras
pip install -e ".[dev]"

# 4. (Optional) Install host ML extras if running Person A's pipeline tools
pip install -e ".[dev,host]"
```

> **Never commit `.venv/` or `.export-venv/`** — both are gitignored.

## 3. Running the Test Suite

### Full host suite (no hardware required) — mirrors CI

```bash
pytest tests/ --ignore=tests/mcp --ignore=tests/target -q
```

Expected: **21+ tests passing**.

### MCP server + workflow tests (extra deps required)

`mcp_server/tests/` and `workflow/tests/` need additional packages not in the base install:

```bash
pip install jsonschema referencing pytest-asyncio pyserial
pytest mcp_server/tests/ workflow/tests/ -q
```

### Hardware-gated tests (extra deps + physical board required)

```bash
pip install jsonschema referencing flatbuffers
pytest tests/mcp/ tests/target/ -q
```

### Contract schema validation

```bash
python contracts/mcp/validate.py
```

Expected: all 10 MCP tool schemas validate against their examples with 0 failures.

### Host parity gate (requires reference golden fixtures)

```bash
python tools/run_host_parity.py --sample-dir reference/artifacts/sample_0001
```

## 5. Branch & Commit Conventions

### Branch naming

| Pattern | Purpose |
|---------|---------|
| `main` | Stable, CI-passing trunk |
| `person-a/work` | Person A feature work |
| `person-b/work` | Person B feature work |
| `person-c/work` | Person C / MCP / Bob work |
| `deploy/kws-stm32u585-<run_id>` | Bob deployment run worktrees (auto-created) |

### Commit messages — Conventional Commits

```
<type>(<scope>): <short summary>

Types: feat · fix · test · docs · chore · refactor · ci
Scope: mcp · firmware · pipeline · parity · contracts · tools · ci · docs

Examples:
  feat(mcp): add real-mode adapter for run_parity_test gate=device
  fix(firmware): correct DWT cycle counter overflow handling
  test(pipeline): add S2 log-mel parity regression test
  docs(contributing): add hardware setup instructions
```

Every commit on a deploy branch must include in the body:
```
Generated by IBM Bob via Code2Edge workflow, run <run_id>
```

## 6. Adding a New MCP Tool

1. **Define the JSON schema** in `contracts/mcp/<tool_name>.schema.json`
   (follow the `$defs/Input` + `$defs/Output` pattern of existing schemas).

2. **Add an example** in `contracts/mcp/examples/<tool_name>.example.json`
   and verify it passes: `python contracts/mcp/validate.py`.

3. **Implement the tool** in `mcp_server/tools/<tool_name>.py`
   (follow the `run()` async pattern + `validate_output()` call).

4. **Register the tool** in `mcp_server/server.py`.

5. **Add a mock fixture** in `mcp_server/mocks/<tool_name>.json`.

6. **Write tests** in `mcp_server/tests/test_<tool_name>.py`.

7. **Update `_TOOL_SCHEMA_FILES`** in `mcp_server/_schema.py`.

## 7. Hardware-Gated Tests

Tests that require the physical Arduino UNO Q on a serial port are excluded from
the standard `pytest` invocation and from CI. Run them manually on the bench machine:

```bash
# Requires physical STM32U585 on COM3 at 115200 baud
pytest tests/target/ tests/mcp/ -q \
  -k "not synthetic"

# Full hardware benchmark (50 iterations)
python tools/target/benchmark_target.py \
  --port COM3 \
  --sketch tests/firmware/benchmark_harness \
  --iterations 50
```

Results are committed to `evidence/benchmarks/` and `evidence/parity/` as authoritative artifacts.
